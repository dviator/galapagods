# Task ID: 68
# Title: Design and Implement Modular World Progression System
# Status: in-progress
# Dependencies: 54, 63, 67
# Priority: high
# Description: Create a comprehensive world progression system with modular architecture supporting sequential world advancement, level-based progression, and configurable enemy encounters including minibosses and bosses.
# Details:
Create src/types/world.ts with core interfaces: World { id: number, name: string, levels: Level[], unlocked: boolean }, Level { id: number, type: 'normal' | 'miniboss' | 'boss', enemies: EnemyConfig[], completed: boolean }, EnemyConfig { type: string, position: Position, stats: Stats }. Implement WorldProgressionManager class in src/utils/worldProgression.ts with methods: getCurrentWorld(), getCurrentLevel(), completeLevel(), advanceWorld(), resetProgression(), isWorldUnlocked(worldId). Design World 1 structure: 9 levels with minibosses on levels 3,6 (Supergoob: { hp: 18, attack: { type: 'aoe', damage: 3 }, position: 'center' }) and boss on level 9 (Goober Supreme: { hp: 24, attack: { type: 'directional', damage: 5, targets: ['left', 'right'] }, position: 'center', minions: [{ type: 'basic_goob', positions: ['left', 'right'] }] }). Create WorldConfig system for easy expansion with JSON-like configuration objects. Implement progression persistence using localStorage with keys: currentWorld, currentLevel, worldsUnlocked, levelProgress. Integrate with existing phase system to trigger world progression on combat completion. Create hooks: useWorldProgression(), useCurrentWorld(), useLevelProgress() for React components. Ensure clean separation: WorldData (static configs), WorldState (current progress), WorldLogic (progression rules). Include validation for world unlocking sequence and level completion requirements.

# Test Strategy:
Unit tests for WorldProgressionManager methods including world advancement, level completion tracking, and reset functionality. Test world unlocking logic ensures sequential progression (world 2 only unlocks after world 1 completion). Verify level generation produces correct enemy configurations for normal/miniboss/boss levels. Test persistence layer with localStorage mock to ensure progression survives page refresh. Integration tests with phase system to verify world progression triggers correctly after combat completion. Test edge cases: completing final level of world, death resetting to world 1, attempting to access locked worlds. Validate World 1 specific configuration: miniboss spawning on levels 3,6 with correct stats, boss level 9 with Goober Supreme and minion positioning. Performance tests for world data loading and progression calculations. Test React hooks for proper state updates and re-rendering when world/level changes.
