# PRD: Roguelike Adventure Game Loop & Structural Refactor

## Overview

Transform the current combat simulator into the foundation of a roguelike adventure game loop. The game will cycle through the following phases:

1. Combat: Player's team fights enemies.
2. Shop: Player buys upgrades for characters and the base ("The Lab").
3. Death: When all player characters die, show a death screen.
4. Lab: Placeholder for future evolution/breeding system.

The UI should always display a phase tracker on the left, indicating the current phase. The main content area will switch between Combat, Shop, Death, and (eventually) Lab screens. Navigation between phases should be automatic based on game state.

## Goals

- Implement the full game loop: Combat → Shop → Combat → ... → Death → Lab → new run.
- Refactor code to separate major functionality into different files/modules.
- Provide a clear, extensible structure for future features (e.g., evolution, new enemy types, advanced combat).
- Maintain a consistent layout with a persistent phase tracker.
- Keep the Reset button for development, which restarts the current combat.
- Implement a UI drag-and-drop system for player interaction with the bench, team sheet, and shop. Shop items should be immediately applied to characters by dragging them over the character card.

---

## Functional Requirements

### 1. Game Loop & Phase Management
- Implement a phase state with possible values: "combat", "shop", "death", "lab".
- Add a phase tracker UI component, always visible on the left, showing the current phase and the overall loop.
- The main content area should render the appropriate screen/component for the current phase.

### 2. Combat Phase
- Use the existing combat simulator as the Combat phase.
- When all enemies are dead, automatically transition to the Shop phase.
- The Reset button should only reset the current combat (for development/testing).
- Implement drag-and-drop: Shop items can be dragged onto character cards to apply effects immediately.

### 3. Shop Phase
- Create a Shop screen/component.
- Display a list of placeholder upgrades for characters and the Lab.
- Allow the player to "buy" upgrades (no need for real currency or inventory yet; just simulate the action).
- After the player clicks a "Continue" button, transition to the next Combat phase with more difficult enemies.
- Implement drag-and-drop: Shop items can be dragged onto character cards to apply effects immediately.

### 4. Death Phase
- When all player characters are dead, transition to the Death phase.
- Show a static image or message indicating the run is over.
- After a short delay or button click, transition to the Lab phase.

### 5. Lab Phase (Placeholder)
- Show a placeholder Lab screen/component.
- Display a message: "Lab/Evolution phase coming soon."
- After a button click, start a new run (reset upgrades, generate a new team, etc.).

### 6. Structural Refactor
- Move major components (Combat, Shop, Death, Lab, PhaseTracker, etc.) into separate files/modules.
- Move types/interfaces into a dedicated types file.
- Move utility functions (e.g., combat logic, enemy generation) into a utils file.
- Keep the main entry file (main.tsx) focused on high-level app structure and routing between phases.
- Architect the app layout so that overlay UI elements (e.g., phase tracker, control panel, visual overlays) can be rendered above or alongside the main phase screens.
- Use a layout/container (ideally in the ContextProvider) to host overlays and the main screen content, maintaining strict separation of concerns between phase screens.

### 7. Extensibility
- Design the structure so that new features (e.g., more complex shop, enemy types, evolution mechanics) can be added with minimal refactoring.
- Use clear, documented interfaces and props for all components.
- Ensure the overlay system and layout/container approach allows for easy addition of new persistent or floating UI elements (e.g., player info, notifications, global controls) without modifying individual phase screens.

#### Future Technical Improvement: Efficient State Updates
For future scalability, consider using shallow updates or the [Immer](https://immerjs.github.io/immer/) library for efficient immutable state updates. Shallow updates and Immer only copy the parts of the state that change, making updates much faster and more memory-efficient for large or deeply nested game states, compared to deep cloning the entire state. This approach is used in modern React/Redux apps and scales better as the game grows.

### 4. Team & Bench Management
- 4 active, 4 bench units; swap only between runs
- Implement drag-and-drop: Player can drag units between the team and bench using a visual interface.

## Non-Functional Requirements
- Use React and Tailwind CSS for all UI.
- Maintain a clean, modern, and consistent UI.
- Ensure all navigation between phases is automatic and robust.
- Code should be easy to read, maintain, and extend.

# Phase 2: Advanced Systems & Progression

## Overview

Building on the core game loop, Phase 2 introduces advanced mechanics to deepen gameplay, progression, and strategic variety. This phase focuses on unique unit abilities, stat and evolution systems, expanded shop and lab features, and new phase mechanics that enhance replayability and player agency.

## Goals
- Add unique abilities and passives for each unit type (Tiger, Bear, Eagle)
- Implement a robust stat and level progression system, including gene grades
- Introduce an evolution system with persistent and randomized growth
- Expand the Shop and Lab with new items, upgrades, and genetic engineering
- Add new phase mechanics (income, death consequences, benching, etc.)
- Build UI for bench and character placement
- Build UI for Shop
- Build UI for Lab
- Build UI for Characters and Gene Editing

---

## Functional Requirements

### 1. Unit Abilities & Passives
- **Tiger**: Specializes in damage; can attack twice per round or gains a bonus for acting first in initiative order.
- **Bear**: Has an area-of-effect (AOE) ability and damage reduction passive.
- **Eagle**: Can attack sideways and provides a utility buff to the team's initiative at the end step.
- **Passive Abilities**: Some passives can trigger at the end step (e.g., heal 1 HP) or after initiative is rolled.

### 2. Stat System & Progression
- **Stats:**
  - Ferocity: Affects attack damage
  - Quickness: Determines initiative
  - Survival: Governs health
  - Instinct: Influences XP gain or ability power (buffs passives like Bear's damage reduction, Eagle's initiative buff, Tiger's damage boost, etc.)
  - Gene-stat (TBD): Provides benefits for evolving and reproducing
- **Leveling:**
  - Each stat is tied to a gene grade (A, B, C, D, F)
  - When a creature levels up (via XP from defeating enemies), the grade determines stat growth:
    - S: 7-8
    - A: 5-6
    - B: 4-5
    - C: 3-4
    - D: 1-2
    - F: 0-1
  - Leveling strength is tied to gene grade

### 3. Evolution System
- Stat growth in each category is randomized per creature and tied to a base grade that persists
- Base attack damage can differentiate characters
- System to display player abilities and evolution progress

### 4. Shop Expansion
- **Income Mechanics:**
  - "Save the Wildlife Fund": Earn more money as you progress
  - Earn income for each enemy defeated
  - Additional income for surviving creatures
- **Items:**
  - Health Potion
  - Attack Booster
  - Income Boosts
  - Evolution Progression Items
  - Items to boost base or random gene grades (improve behind-the-scenes base stats, persistent across runs)
  - New animal unlocks

### 5. Lab Expansion
- **Phases:**
  - Heal up to 2 creatures per session
  - Display which creatures are on the bench (aging mechanics)
  - Recruit 1 new creature (maybe 2 after the first round)
  - Genetically engineer 2 creatures (1 slot at first, unlock more over time)
  - Upgrade facilities, create items, upgrade units
  - Team setup and bench management

### 6. Phase Mechanics & Death Consequences
- Earn income for each enemy defeated and for surviving creatures
- If a creature dies, it is benched for the next X runs (duration increases with repeated deaths)
- Recruit new creatures every run; bench damaged ones
- Consequences and management of death and benching

### 7. Implementation Tasks
- Build bench and character placement panel
- UI for displaying abilities, stats, and evolution progress
- Shop and Lab UI/logic for new items and upgrades
- Systems for stat progression, gene grades, and evolution
- Passive and triggered ability systems (end step, initiative roll, etc.)

---

## Non-Functional Requirements (Phase 2 Additions)
- Maintain extensibility for future units, abilities, and shop/lab features
- Ensure new UI components are consistent with existing design
- All new systems should be modular and testable

---

## Out of Scope (for this phase)
- Persistent save/load (unless required for progression testing)
- Advanced enemy AI or new enemy types (focus is on player units and systems)
- Multiplayer or online features

---

## Acceptance Criteria
- Each unit type has unique abilities and passives implemented
- Stat, level, and evolution systems are functional and visible to the player
- Shop and Lab support new items, upgrades, and genetic engineering
- Phase mechanics (income, death/benching, recruitment) are operational

# Technical Notes (Architecture & Design)

## Major Architectural Decisions
- **Automated Combat**: Combat is fully automated; no player input during combat. All logic is handled by the combat engine.
- **Phase Management**: Centralized phase state and transitions using React context. All phase transitions are automatic and robust.
- **Team & Bench Management**: Team and bench are managed in global state. Bench capacity is limited and only swappable between runs.
- **Modular Unit & Ability System**: Units, attacks, and passives are defined as modular, extensible objects. Passive abilities are designed to be unique per unit but can be swapped/shared in future.
- **Stat System**: All core attributes (health, initiative, etc.) are stat-based and configurable. Stat scaling is managed via a central config.
- **Shop & Lab Extensibility**: Shop and Lab are designed for easy addition of new items, upgrades, and genetic mechanics. Petri Dish item is implemented in Shop for future Lab integration.
- **UI Structure**: Persistent phase tracker, modular phase screens, and clear separation of concerns between UI and logic. All UI follows current design cues for clarity and legibility.
- **Testing & Extensibility**: Core logic is covered by unit tests. Architecture is documented and ready for future expansion (aging, gene editing, win state, etc.).

- Major version: Milestone features or overhauls

# Phase 4: Enhanced Combat & Strategic Depth (V1.1)

## Overview
Phase 4 (V1.1) introduces a major overhaul to the combat system, evolution mechanics, and item progression based on 7/25 design review. The focus is on creating deeper strategic choices, more variable runs, and a tighter integration between evolution and combat mechanics.

## Goals
- Redesign combat system with real-time mechanics (running timer, clickable ability buttons)
- Make evolution system directly impact combat strategy and choices
- Introduce Balatro-style "joker" modifiers for global run bonuses
- Add heritable genetic weaknesses as strategic tradeoffs
- Implement hybrid creature combinations with unique abilities
- Expand item system with limited shop stock and variable rewards
- Add mid-run perk/talent choices for in-run unit differentiation
- Create more engaging and varied run experiences

## Key Features

### Combat System Redesign
- Implement turn-based combat with variable attack countdowns instead of fixed rounds
- Each unit has an attack speed stat that determines countdown timer to next action
- Attack resolution proceeds in order of countdown completion (asynchronous turn order)
- Clear visual display of attack countdowns so players can anticipate next actions
- Supports multiple active attacks per character (each with independent counters)
- Enables interesting choices during run (speed items, stat allocation) that affect combat pacing

### Evolution & Genetics Enhancements
- Heritable genetic 'weaknesses' that provide drawbacks as strategic tradeoffs
- Perk/Talent choices at new levels during runs to differentiate monsters in-run
- New species unlock unique abilities and traits that can be copied/edited/cloned into other units
- Hybrid creature combinations (Tiger/Eagle → Gryphon, Lizard/Bird → Dragon)
- Mythical creatures have unique/fantastical attack types (fire breath, laser beam eyes)

### Item & Progression System
- "Joker" style modifiers that apply powerful global bonuses to specific attack/ability types
- Limited shop item stock - no infinite purchasing (strategic scarcity)
- Variable coin rewards based on enemy level with potential bonus achievements
- Items that impact evolution and stat growth

### Run Variety & Replayability
- Each run is more variable and full of strategic choices
- Multiple viable strategies per run based on items and perks available
- Genetic traits create diverse team possibilities across runs
- Hybrid combinations unlock new strategies and playstyles

## Functional Requirements

### 1. Combat System
- Turn-based combat with variable attack countdowns
- Attack speed stat determines countdown duration to next action
- Actions resolve in countdown completion order (not fixed turn order)
- Multiple active abilities per character, each with independent countdowns
- Clear visual countdown displays for player anticipation
- Combat speed varies based on team composition and stat choices

### 2. Evolution System Integration
- Genetic weaknesses appear as heritable traits with drawbacks
- Perk/Talent system for mid-run unit differentiation
- New species unlock transferable abilities
- Gene visibility shows which traits are heritable

### 3. Item System
- Joker modifiers with global attack/ability type bonuses
- Limited shop stock per run (limited potions, items, etc.)
- Variable rewards: gold scales with enemy level
- Bonus achievement rewards for combat performance

### 4. Hybrid Combinations
- Tiger + Eagle = Gryphon with combined abilities
- Lizard + Bird = Dragon with fire breath
- New mythical attack types (laser eyes, elemental effects, etc.)
- Hybrids unlock in Lab for future generations

## Out of Scope (for this phase)
- Complex enemy variety (focus on player systems)
- Persistent save/load
- Aging system (defer to V2)

## Acceptance Criteria
- Turn-based combat with variable attack countdowns is fully functional
- Attack speed stat meaningfully affects combat pacing and strategy
- Countdown displays are clear and help players anticipate actions
- Evolution and combat systems feel deeply integrated
- Joker items provide meaningful run-altering choices
- Each run feels significantly different based on team composition and items
- Hybrid creatures are visually distinct and mechanically unique
- Combat is engaging without requiring real-time reflexes
